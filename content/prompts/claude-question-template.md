# 문제 생성 프롬프트 템플릿

아래 블록 전체를 Claude에 붙여 넣고, `{{ }}` 다섯 곳(주제·난이도·초성 수·객관식 수·OX 수)만 바꿔서 보내세요. 요청 1번에 표의 한 칸(주제 × 난이도)을 만듭니다. 칸별 수량은 `content/GUIDE.md`의 요청표를 보면 됩니다.

같은 대화에서 이어서 요청하면 Claude가 앞 문제와 겹치지 않게 만들기 쉽습니다. 새 대화에서 만들 때 중복이 걱정되면, 블록 끝의 `[중복 방지]` 줄에 기존 문제 문장을 붙여 넣으세요. 필요 없으면 그 줄을 지우면 됩니다.

---

```
너는 한국어 교양 퀴즈 앱 '쥐락펴락'의 문제 출제자야. 아래 조건으로 문제를 만들어 JSON 배열 하나만 출력해. 설명, 머리말, 코드펜스 바깥 텍스트는 쓰지 마.

[이번 요청]
- topic: {{주제}}            (상식 | 어휘력 | 역사 | 과학 중 하나)
- difficulty: {{난이도}}     (1, 1.5, 2, … 5 중 하나. 모든 문제에 같은 값)
- 개수: 초성 {{초성 수}}개, 객관식 {{객관식 수}}개, OX {{OX 수}}개
- subfield: 이 주제의 세부 분야를 최대한 고르게 섞어
  - 상식: 생활 / 사회 / 문화
  - 어휘력: 맞춤법 / 한자어 / 순화어
  - 역사: 한국사 / 세계사
  - 과학: 물리 / 화학 / 생물

[난이도 기준]
- 1: 초등학교 고학년이면 대부분 앎
- 2: 중학생이면 대부분 앎
- 3: 일반 성인의 절반 정도가 앎
- 4: 그 분야에 관심 있는 성인이 앎
- 5: 애호가·전공자 수준
(0.5 단위는 그 사이)

[문제 객체 형식]
{
  "topic": "과학",
  "subfield": "화학",
  "type": "chosung" | "mcq" | "ox",
  "difficulty": 3.5,
  "question": "문제 문장",
  "answer": "정답",
  "choices": ["보기1", "보기2", "보기3", "보기4"],   // mcq일 때만. 다른 유형은 이 키를 아예 빼
  "explanation": "정답의 근거를 1~3문장으로",
  "source": { "title": "근거 자료 이름", "url": "" }
}

[유형별 규칙]
1) chosung (초성퀴즈)
   - answer는 한글 음절만 2~10자. 띄어쓰기·숫자·영문·괄호 금지.
   - 앱은 정답과 '완전히 일치'할 때만 정답으로 인정해. 그러니 정답이 하나로 딱 떨어지게 문제를 써.
     예) "세종"/"세종대왕"처럼 여러 형태가 가능하면 문제에 "묘호로 답하시오"처럼 형태를 지정해.
   - question에 정답이나 정답의 초성을 쓰지 마. (초성은 앱이 자동으로 보여줘)
2) mcq (객관식)
   - choices는 정확히 4개, 서로 달라야 하고, answer는 choices 중 하나와 글자까지 똑같아야 해.
   - 오답 보기는 그럴듯하게. "모두 정답", "정답 없음" 같은 보기 금지.
   - 정답 위치를 골고루 섞어.
3) ox
   - question은 참/거짓을 판단할 수 있는 한 문장의 진술문.
   - answer는 "O" 또는 "X". 이번 요청 안에서 O와 X를 비슷한 수로.
   - choices 키 없음.

[품질 규칙]
- 사실관계가 확실한 것만. 학설이 갈리거나 시기에 따라 바뀌는 내용(최신 순위, 통계 등)은 피해.
- 어휘력은 국립국어원 표준국어대사전·우리말샘 기준으로 판단해.
- source.title에는 실제로 확인할 수 있는 자료 이름을 써 (예: "표준국어대사전", "고등학교 화학Ⅰ 교과서", "조선왕조실록").
- source.url은 확실히 존재하는 주소일 때만 쓰고, 조금이라도 불확실하면 빈 문자열 "" 로 둬. 주소를 지어내지 마.
- 한 요청 안에서 같은 지식을 묻는 문제를 중복으로 만들지 마.
[중복 방지] 다음 문제들과 같은 내용을 묻지 마: (기존 question 문장들을 붙여 넣거나, 필요 없으면 이 줄을 삭제)

출력: JSON 배열 하나.
```
