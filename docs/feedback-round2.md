# 2차 피드백 요구사항 (2026-10-18)

사용자 피드백 10건의 확정 요구사항, 결정, 담당, 성공 기준. 기능 동결은 10/27. 일정이 밀리면 맨 아래 "자르는 순서"를 따른다.
스펙과 다른 점은 이 문서가 우선한다(사용자 결정): 치즈 획득 경로 확대, 솔로 한정 소모 아이템, 대결 초성 힌트 시점의 의미 변경, 문제 난이도 0.5 단위.

## 확정된 사용자 결정
- **D-R2-1 초성 힌트 시점 = "화면의 남은 시간이 N초가 될 때"** (제한시간 60초, N=45 → 경과 15초에 공개). 타이머는 남은 시간으로 카운트다운 표시(60→1). 방 설정의 힌트 옵션은 제한시간보다 작은 값만 선택 가능하고 '힌트 없음'이 있다. 저장 의미: `chosungRevealSec`는 **남은 시간(초)**. 엔진 내부 공개 시점(경과) = 제한시간 − N. 힌트 공개 전 정답 +30점 규칙은 그대로.
- **D-R2-2 상점 소모 아이템은 솔로 한정**, 대결에서는 사용 불가. 문제에 사용하면 그 문제의 노힌트 보너스(+20%)가 없어지고, 스테이지 클리어 기준(7/10)과 나머지 XP 규칙은 그대로.

## 기본값(설정 파일에서 조정 가능, 사용자가 별도 의견 없으면 이대로)
- 상점 가격: 연속학습 보호권 50 치즈(기존 규칙: 최대 2개 보유, 하루가 끝날 때 자동 사용) / 초성 첫 글자 공개권 15 치즈 / 오답 보기 제거권 15 치즈. 소모 아이템 보유 상한 99.
- 아이템 사용: 문제당 같은 종류 1회. 초성 첫 글자 공개권 = 초성퀴즈에서 정답의 첫 글자(자음이 아닌 실제 글자)를 보여줌 / 오답 보기 제거권 = 객관식에서 정답이 아닌 보기 1개를 제거(서버가 선택, 정답은 절대 제거 안 함).
- **상자는 스테이지 최초 클리어 때만** 지급(XP와 같은 기준: 다시 깬 스테이지, 레벨테스트·기초 테스트로 건너뛴 스테이지는 지급 없음). 일반 상자는 매 최초 클리어마다, **좋은 상자는 스테이지 레벨이 5의 배수일 때**(일반 상자 대신).
- 상자 보상표(서버 난수, 열 때 결정하고 DB에 저장해 다시 열 수 없음):
  - 일반: 70% 치즈 5~15(균등) / 20% 초성 첫 글자 공개권 1 / 10% 오답 보기 제거권 1
  - 좋은: 치즈 20~50 확정 + 50% 확률로 소모 아이템 1(공개권/제거권 반반) + 10% 확률로 보호권 1(보유 상한 2에 걸리면 치즈 30으로 대체)
- 상자는 열기 전까지 보관함에 남는다(결과 화면에서 바로 열거나 상점의 보관함에서 나중에 열 수 있음).
- 연속학습 달력의 일 상태: 학습함(KST 하루에 인정 활동 있음) / 보호권 사용 / 놓침 / 오늘 / 미래.

## 새 API 계약 (LB 구현, LG가 사용)
모든 경로는 `/api` 아래, 회원 로그인 필요. DTO는 `packages/shared/src/dto/shop.ts` 등에 LB가 가장 먼저 추가한다.
- `GET /me/streak/calendar?month=YYYY-MM` → `{ month, days: [{ date, state: 'studied'|'protected'|'missed'|'today'|'future', sets?, battles? }], current, longest, protectionsHeld, nextMilestone: { days, cheese, daysLeft } | null }` (KST 기준)
- `GET /shop` → `{ cheese, items: [{ kind: 'streak_protection'|'chosung_first'|'remove_wrong_choice', name, desc, price, owned, max }], chestsUnopened: number }`
- `POST /shop/items/:kind/purchase` `{ quantity? }` → `{ cheese, owned }` (치즈 부족 402, 보유 상한 409, 치즈 원장 `item_purchase`)
- `GET /me/inventory` → `{ items: [{kind, owned}], chests: [{id, tier:'normal'|'good', source: {topicId, level}, grantedAt}] }`
- `POST /me/chests/:id/open` → `{ rewards: [{ type:'cheese', amount } | { type:'item', kind, quantity } | { type:'protection' }], cheese, inventory }` (이미 열림 409)
- 스테이지 완료 응답(`/solo/sets/:id/complete`)에 `chest?: { id, tier }` 추가(최초 클리어에만)
- `POST /solo/sets/:id/items/use` `{ questionId, kind: 'chosung_first'|'remove_wrong_choice' }` → `{ chosungFirst?: string, removedChoice?: string, owned }` (대결/방에서는 404, 없는 아이템 409, 문제당 같은 종류 중복 409, 해당 유형이 아니면 400). 사용한 문제는 힌트 사용으로 기록(노힌트 보너스 제외)
- 치즈 원장 사유에 `chest_reward`, `item_purchase` 추가, 상자·소모 아이템 보관은 새 테이블(마이그레이션은 LB만 생성)

## 자르는 순서 (일정이 밀릴 때)
10 배경음 → 3의 좋은 상자 차등 → 9의 일부 효과음 → 4의 세부 연출 → 2의 아이템 상품(보호권 외). 핵심 시연 흐름과 1·5·6·7·8은 자르지 않는다.
