# 수동 QA 체크리스트

배포본(`PUBLIC_ORIGIN`)에서 실기기로 확인한다. 결과는 칸에 O/X와 메모로 남긴다. 시연 순서와 관측값은 `docs/demo-runbook.md`를 따른다.

## 기기 구성
| 역할 | 기기 | 브라우저/앱 |
|---|---|---|
| 회원 A | Android 실기기 | APK(주) 또는 Chrome 웹(폴백) |
| 게스트 B | iPhone | Safari 웹 |
| 보조 | 다른 Android | Chrome, 카카오톡 인앱 브라우저 |

## AC-A8 딥링크·접속 경로
- [ ] Android, 앱 설치됨: 초대 링크 `PUBLIC_ORIGIN/join/<코드>` 탭 → 앱이 열리고 방 입장 화면으로 이동
- [ ] Android, 앱 미설치: 같은 링크 → 웹으로 열리고 게스트로 입장 가능
- [ ] `PUBLIC_ORIGIN/.well-known/assetlinks.json`이 200이고 `sha256_cert_fingerprints`에 설치한 APK 서명 지문 포함(`apksigner verify --print-certs <apk>`와 대조)
- [ ] iOS Safari(게스트): 초대 링크 → 웹으로 열림(iOS는 웹만, 앱 딥링크 없음). 닉네임 입력 후 입장, 풀이, 결과 화면까지 진행
- [ ] iOS Safari: 키보드·주소창 때문에 화면이 잘리거나 입력창이 가려지지 않음, 소켓이 백그라운드 복귀 후 재접속
- [ ] 카카오톡 인앱 브라우저: 링크가 인앱에서 열릴 때 외부 브라우저로 열기 안내가 나오고 따라 하면 Chrome/Safari에서 열림
  - [ ] 실패 시 폴백: 같은 링크를 문자(SMS)로 보내 열기, 또는 방 화면의 QR 코드를 다른 기기로 스캔해 열기
- [ ] Android 회원 A: 카카오 로그인 후 앱으로 복귀(콜백 후 세션 유지)

## 로그인
- [ ] 카카오 로그인이 첫 번째 버튼이고 성공(웹, 앱 각각)
- [ ] 네이버 로그인 성공(실기기 검증 불가 시 웹만, 사다리 10)
- [ ] Google 로그인 성공 또는 `onrender.com` 거부 사실 기록(`demo-runbook` 4절)
- [ ] 게스트 결과 화면의 "로그인하고 기록 저장하기" 후 기록이 계정으로 병합됨

## AC-G9 아이템 이미지 교체(재배포 없이)
- [ ] 관리자 웹(`PUBLIC_ORIGIN/admin/`) Items에서 아이템 하나의 이미지를 교체해 업로드
- [ ] 재배포 없이 앱/웹의 캐릭터 꾸미기 화면에서 새 이미지가 보임(캐시 키가 바뀌어 새 URL)
- [ ] 이전 이미지 URL은 계속 200(immutable 캐시), 새 URL은 `Cache-Control: public, max-age=31536000, immutable`

## 대결 흐름(두 기기 동시)
- [ ] 방 생성 → 코드 입장, 링크 입장 둘 다 성공
- [ ] 두 기기에서 문제·타이머가 거의 동시에 진행되고 점수가 서버 기준으로 일치
- [ ] 한 기기 네트워크를 잠깐 끊었다가 복귀하면 이어서 진행
- [ ] 결과 화면 순위와 서버 기록(오답노트, XP)이 일치

## 슬립·콜드 스타트
- [ ] keepalive를 끄고 20분 후 첫 접속 시간 기록(`demo-runbook` 4절)
- [ ] 슬립 직후 첫 WebSocket 연결이 재접속 백오프 안에서 성공

## 화면 확인
- [ ] 작은 폰(너비 360)과 큰 폰에서 주요 화면 줄바꿈·잘림 없음
- [ ] 한글 폰트가 웹과 앱 모두 표시됨(깨짐 없음)
