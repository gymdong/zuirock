# 쥐락펴락(zuirock) 프로젝트 현황 — 새 세션은 이 문서부터 읽는다

최종 갱신: 2026-10-28. **시연 11/4로 연기(10/28 결정)**, 기능 동결 11/2, 리허설 11/2~3, iPhone 재설치 11/2(무료 서명 7일 만료 대비). 옛 일정(동결 10/27·시연 10/29)을 표기한 아래 날짜 중 'D12·D14' 같은 표기는 옛 기준이다. 비밀 값은 이 저장소 어디에도 없다.

## 1. 한 줄 요약
교양 지식 솔로 학습(주제별 스테이지: 공개 문제 15개당 1개, 10/28 개편) + 친구와 실시간 퀴즈 대결 모바일 서비스. 모든 풀이는 풀이 로그로 쌓여 XP·스트릭·오답노트·리포트로 돌아온다. 사용자는 **혼자 개발을 지시하는 비개발 PM**이고 한국어로 소통한다. 서비스 이름은 `zuirock`(패키지 `@zuirock/*`), 제품명 "쥐락펴락".

## 2. 지금 배포된 상태 (모두 동작 확인됨)
| 항목 | 값 |
|---|---|
| 웹/서버 | Render 무료 웹 서비스 `zuirock`, 싱가포르. 주소 `https://zuirock.onrender.com` (API·Socket.IO·웹앱·`/admin/` 모두 한 곳) |
| DB | Neon 무료 PostgreSQL, **싱가포르** (미국 동부에서 옮겨 응답이 1.3~1.7초 → 0.2초) |

| 배포 브랜치 | `feat/zuirock-mvp` (push하면 Render가 자동 배포). 저장소 `github.com/gymdong/zuirock` |
| 로그인 | 카카오 동작 확인. 네이버·Google은 키 미설정(503 "준비 중") — 시연엔 불필요 |
| 문제 | 600개 공개됨(상식·역사·어휘력·과학 각 150, 난이도 ★1~5 0.5단위, 초성60/객관식61/OX29). 파일은 `content/incoming/*_questions.json` |

| 환경 변수(Render) | `NODE_ENV=production, PUBLIC_ORIGIN, DATABASE_URL(pooled+pgbouncer), DIRECT_URL, REDIS_URL, JWT_SECRET, STATE_SECRET, GUEST_TOKEN_SECRET, KAKAO_CLIENT_ID/SECRET`, 시연 준비 기간엔 `DEMO_SEED=1`. **`DEV_LOGIN`은 절대 넣지 않는다**. 값은 사용자가 Render 대시보드에만 입력 |
| 시연 데이터 | 관리자 화면 `/admin/` → "시연 데이터" → `초기화` 입력 → 호출한 계정에 시연 상태 적용(약 6초, 확인표 ✓). 리허설 후/시연 직전에 사용. 끝나면 `DEMO_SEED` 제거 |

## 3. 완료된 작업
- 계약·모노레포: pnpm+Turborepo, Prisma 6, NestJS 12 ESM, Expo SDK 57(웹 output "single"), 공용 타입 `packages/shared`
- 규칙 `packages/game-rules`: 점수·XP(일일 상한 3000, 7일 감쇠)·게스트 병합·종합 세트 배분(D6-10 (c))·스트릭·초성 판정·리포트·상자 보상·아이템 도우미 (390 테스트)
- 서버: 인증(카카오 우선, PKCE, 게스트 서명 토큰), 솔로(스테이지/레벨테스트/종합/3분 지식/퀘스트), XP·치즈·스트릭, 리포트·약점, 게스트 병합, 오류 신고, 기록 삭제·탈퇴, 친구, 캐릭터·치즈 구매, **상점·소모 아이템·스테이지 상자·연속학습 달력**, 관리자 API(일괄 공개 `bulk-transition`), 정적 서빙, **시연 시드(`DEMO_SEED`)** (105 테스트)
- 실시간: 방 엔진, 버전 CAS+임대 펜스, 재접속, 결과 기록 재시도, 초대함. **초성 힌트 = 화면의 남은 시간이 N초가 될 때** (D-R2-1), 난이도 0.5단위
- 클라이언트: 목업 16화면 + 상점·연속학습·설정, 대결 연출·카운트다운 타이머·문제 수/난이도 막대·애니메이션, 뒤로가기 정리, **효과음 13개+로비 배경음(직접 합성, 저작권 없음, `docs/audio.md`)**
- 관리자 웹: 문제 업로드·검수·일괄 선택 공개·시연 데이터 페이지·자동 로그인
- 검증: `pnpm e2e:local`(6 passed), 전체 22개 작업 통과, Docker 이미지 기동, 운영 DB 증분 마이그레이션(기존 데이터 보존) 확인

13. **스테이지 묶음 방식으로 개편(10/28, 시연 연기로 가능해진 변경)**: 옛 방식(주제 Lv.1~99, 레벨마다 ★ 구간에서 그때그때 10문제 뽑기)을 없애고, 주제의 공개 문제를 난이도 순(같은 난이도 안에서는 세부 분야 번갈아)으로 **15개씩 잘라 스테이지 1, 2, 3…**으로 만든다(`packages/game-rules/src/stage.ts`의 `planStages`, 서버 `StagePlanner`가 공개 문제로 매번 계산 → 새 문제 공개·중지 즉시 반영, DB 변경 없음). 스테이지 수 = 공개 문제 ÷ 15(150문제 = 10개, 450문제 = 30개, 남는 문제는 마지막들에 1~14개씩 분배). 한 판은 그 스테이지 묶음에서 10문제(아직 못 맞힌 문제 우선, 쉬운 것부터), 7개 맞히면 클리어, 다시 도전하면 일부가 바뀐다. 레벨테스트 추천 = 평균 난이도에 처음 닿는 스테이지, 기초 테스트 체크포인트 = **5스테이지마다**(5, 10, …)이고 그 아래 5개 스테이지 문제에서 출제, 좋은 상자도 5의 배수 스테이지. 종합·3분 지식·퀘스트·진단은 현재 스테이지 앞뒤 난이도 범위에서 뽑는다. 마지막 스테이지를 깨면 '완료'지만 문제가 늘어 스테이지가 생기면 다시 열린다(`topicLevel`을 읽을 때마다 계산). `TopicProgressDto`에 `stageCount`·`checkpoints`·`stage`(난이도 범위) 추가, 설정 버전 `2026-10-28.1`(`stage.bands`·`maxLevel`·`placement.table` 삭제, `stage.poolSize`·`basicTest.every` 추가). 기존 `highestClearedStage` 값은 그대로 쓰고(스테이지 수보다 크면 완료로 보임), 시연 데이터 주제 레벨은 6·4·3·5로 낮춤. **운영 반영 때 알아 둘 점**: 옛 진행도(Lv.20 등)는 스테이지 수(10)를 넘으면 '모두 깸'으로 보이므로 시연 데이터 초기화를 다시 한다. 스테이지 묶음은 문제 수에 따라 조금씩 이동하므로 문제를 대량 공개한 뒤에는 클리어한 스테이지 번호가 가리키는 문제가 바뀔 수 있다
12. **풀이 중 나가기 확인(10/27)**: 솔로 세트·대결 진행 중 뒤로/나가기(✕)/안드로이드 뒤로를 누르면 확인창(`components/LeaveGuard.tsx`). 솔로는 그만두면 세트를 버린다(`POST /solo/sets/:id/abandon`, 푼 기록 삭제·`abandoned`). 대결은 기존 `room:leave`(중도 퇴장). 풀이 중 iOS 스와이프 뒤로는 꺼 둔다. 웹 브라우저 뒤로가기는 라우터가 확인을 건너뛰어 창 없이 나가지만 세트는 버려진다(새로고침·탭 닫기는 브라우저 확인). 고친 버그: 오늘의 3분 지식을 풀다 나갔다 오면 진행 중 세트를 이어 주면서 화면은 1번부터 다시 보여 '이미 답한 문제예요'가 떴다 → 이어 풀기 없이 새 세트를 준다
10. **치즈 마을 테마 전체 개편(10/26, 사용자 결정으로 기능 동결 연기)**: 버터 크림 바탕 + 천천히 떠다니는 치즈 구멍 배경(모든 화면, 10/26 오후 시안 적용으로 제거), 카드 위 녹은 치즈(`CheeseCap`), 섹션 제목 치즈 아이콘, 치즈 길 스테이지 지도. 반응형 효과(`components/fx.tsx`): 치즈 부스러기 폭발(색종이 대체), 점수 날아가기, 쥐 깜짝 등장 반응, 연속 정답 피버 테두리(3연속 노랑·5연속 주황 FEVER), 시간 압박 붉은 비네트, 레벨업·우승 전체 화면 축하. 팔레트는 바탕색 조정 + 치즈 계열 색 추가(보라·노랑 유지). 화면 전체 덮개는 `Screen`의 `overlay`

## 9. 작업 방식 (에이전트 팀)
- 레인: LA 규칙(`packages/game-rules`), LB 서버 REST(`apps/server/src/modules/*`, prisma 마이그레이션은 LB만), LC 실시간(`modules/rooms`), LD 클라이언트(`apps/mobile`), LE 관리자·콘텐츠(`apps/admin`, import), LF 인프라·시드·QA(`infra`, `e2e`, `scripts/seed`, docs), LG 경제 UI·오디오. 레인은 자기 디렉터리만 수정, 커밋은 리드만
- 의존성 설치는 `.omc/state/pnpm.lock` 디렉터리 잠금 후 한 번에 하나, 필터 설치 뒤에는 루트에서 `pnpm i`
- **사용량 한도가 여러 번 작업을 끊었다.** 동시에 3~4개 레인만 돌리고, 지시에 "토큰 절약"을 넣고, 한도 후 재개 시 로컬 임시 커밋(`wip`)으로 보존한 뒤 이어서 시킨다
- 레인 보고는 그대로 믿지 말고 리드가 테스트·E2E를 직접 다시 돌려 확인한다(이번에도 실서버 연결 확인으로 서버 버그 2건을 찾음)
